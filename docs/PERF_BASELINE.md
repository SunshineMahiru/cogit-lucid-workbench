# 启动耗时基线

记录日期：2026-11-13。构建 `d4b6069`，模拟器 Mate 70 Pro，应用为当前 debug 签名包。

## 方法

冷启动用 `aa force-stop` 杀掉进程，等 4 秒让系统回收，再计时下面这条命令：

```bash
hdc shell aa start -a EntryAbility -b com.sunshinemahiru.cogitlucid -W
```

`-W` 会等到应用进入前台才返回，所以计的是「命令发出」到「首页可交互」的墙钟时间。同一台机器上 `hdc shell echo ok` 往返约 320 ms，是这条链路的固定开销，下表同时给出扣掉它之后的值。

每次启动后立刻 dump 一次布局，确认「记录者」已在树上，说明计时终点不是白屏。

## 结果

| 场景 | 三次实测 | 中位 | 扣除传输开销 |
|---|---|---|---|
| 冷启动（杀进程后） | 1502 / 1785 / 1448 ms | 1502 ms | 约 1.18 s |
| 热启动（退到桌面再回） | 1324 ms | 1324 ms | 约 1.00 s |
| 传输基线（`echo ok`） | 327 / 330 / 312 ms | 327 ms | — |

## 说明与局限

- 冷启动这三次的离散度接近 300 ms，模拟器本身不是稳定计时环境；要看趋势就得在同一台机器、同一时段重复测。
- `-W` 的返回点服从系统调度，不是精确的首帧时刻；这里把它当作上限，真实首帧不会更晚。
- 热启动 1 s 里包含一次首页刷新（前台回来会重算统计），没有拆开。
- 页面切换、列表滚动帧率、内存占用都还没测。
