## 2. DB 21 合并迁移

### 2.1 变更

| 表 | 列 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| `request_audit` | `removed_count` | INTEGER | 0 | 确认清单移除条数；旧行读 0 |
| `decision_record` | `depth` | TEXT | NULL | quick/normal/deep；旧行为 NULL，回退 payload |
| `decision_record` | `time_budget` | INTEGER | NULL | 分钟；0 表示无预算；旧行为 NULL |

`interaction_log` 不加列：它是 `relation` 表里的 JSON 文本，新增可选 `level` 只改解析与序列化。

### 2.2 迁移 SQL

```sql
ALTER TABLE request_audit ADD COLUMN removed_count INTEGER NOT NULL DEFAULT 0;
ALTER TABLE decision_record ADD COLUMN depth TEXT;
ALTER TABLE decision_record ADD COLUMN time_budget INTEGER;
```

执行方式：`DB_VERSION` 从 20 改为 21；在 `DbHelper.setup` 的迁移区新增一个 `db21Migrations` 数组，逐条 `try/catch`，与现有幂等写法一致。新装环境的 `TABLE_CREATE_SQLS` 同步加入三列。

### 2.3 回滚 SQL

```sql
ALTER TABLE request_audit DROP COLUMN removed_count;
ALTER TABLE decision_record DROP COLUMN depth;
ALTER TABLE decision_record DROP COLUMN time_budget;
```

回滚前必须先备份。SQLite 的 `DROP COLUMN` 在旧版本可能不可用；若失败，保留三列不影响旧代码读取，只把 `DB_VERSION` 降回 20 不解决问题，需用备份恢复。

### 2.4 模型与 DAO

| 文件 | 改动 |
|---|---|
| `model/RequestAudit.ts` | 增加 `removedCount: number` |
| `db/dao/RequestAuditDao.ts` | insert 写 `removed_count`；mapRow 用 `getLong` 读，缺列时按 0 |
| `model/DecisionRecord.ts` | 增加 `depth?: WorkDepth`、`timeBudget?: number` |
| `db/dao/DecisionRecordDao.ts` | insert 写两列；mapRow 用 `readText`/`readLong`，空值不填 |
| `review/ReviewService.ts` | `decisionRow` 接收 `payload.depth`、`payload.timeBudget` 并写入 |
| `review/ReviewAgent.ts` | `recordAudit` 增加 `materialIds`、`levels`、`removedCount` 参数；调用处从确认清单传入 |
| `components/ReviewAgentPanel.ets` | `analyze` 增加 `removedCount`；把保留项的 id/level 传给 Agent |

### 2.5 兼容顺序

| 场景 | 读取顺序 |
|---|---|
| 旧审计行 | `removed_count` 缺失 → 0；`material_ids`/`levels` 为空 → 保持空，不猜测 |
| 旧决定行 | `depth`/`time_budget` 为 NULL → 读 `ReviewPayload.depth/timeBudget`；payload 也没有 → normal/0 |
| 新决定行 | 列有值 → 列优先；payload 仅作回退 |
| 旧互动 JSON | 条目无 `level` → 跟随 `relation.level`；有 `level` → 条目优先 |
| 旧导出文件 | 不含新字段，读取方按空值处理 |

## 3. 互动密级（R16）

- `InteractionLog` 增加 `level?: SecurityLevel`。
- `parseInteractionLog` 只接受 `local_only`/`analyzable`/`sealed` 三个值；其他值忽略。
- 序列化继续 `JSON.stringify`，不新增表、不改 `interaction_log` 列。
- 过滤规则：`sealed` 条目不进导出、不进 Agent；`local_only` 条目仅在 `includeLocalOnly` 时进导出，永不进 Agent；缺省回退 `relation.level`。
- 关系详情编辑器按条目给三档；旧条目显示“跟随关系”。

## 4. 公共分享副本（R13）

### 4.1 默认规则

| 字段 | 公共副本默认 | 可选 |
|---|---|---|
| 仅本地内容 | 不写入 | 否 |
| 对方陈述 | 不写入 | 仅允许转述，不允许原文 |
| 示例数据 | 不写入 | 否 |
| 关系名 | 使用已脱敏别名 | 否 |
| 锚点选择理由 | 不写入 | 是 |
| 请求审计元数据 | 不写入 | 否 |
| 封存内容 | 永不写入 | 否 |

### 4.2 实现位置

- 新增 `PublicShareOptions`（默认全部安全值）与 `preparePublicBundle(bundle, options)`，放在 `export/`。
- `ExportService` 增加 `exportPublicMarkdown(context, now, options)`，复用渲染器，但先走 `preparePublicBundle`。
- `SettingsPage` 的分享按钮改为“公共副本预览”，预览文件、字符数、记录数、隐藏的对方陈述条数；确认后调用新方法，不直接分享完整导出。
- 不修改 `exportMarkdown` 的默认行为，避免影响本地完整导出。

### 4.3 验收

| 检查 | 预期 |
|---|---|
| 对方陈述 | 公共副本不出现原文；转述也需显式勾选 |
| 仅本地 | 默认不出现；无“全部包含”入口 |
| 关系名 | 只出现别名；不回落真名 |
| 锚点理由 | 默认不出现；勾选后才出现 |
| 请求元数据 | 不出现 host、材料编号、审计行 |
| 封存 | 任何选项都不出现 |

## 7. 风险

| 风险 | 处理 |
|---|---|
| DB 21 迁移失败 | 迁移逐条 try/catch；失败列记录到 `migrationFailures`，界面提示备份 |
